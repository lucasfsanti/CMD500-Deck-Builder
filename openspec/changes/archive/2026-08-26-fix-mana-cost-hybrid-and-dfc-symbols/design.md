## Context

See proposal.md for motivation. Relevant existing shape (from the mana-cost-icons feature this fixes a gap in):
- `extractManaCost` (`extension/src/lib/capture/mana-cost.ts`) reads `.deck-cmc .txt-mana abbr.mtg-symbol` elements and decodes each one's class-name slug (`mtg-symbol-<slug>`) via a `SLUG_TO_SYMBOL` lookup table. If any single pip's slug isn't in the table, the whole card's cost is dropped (`undefined`) rather than shown partial — the deliberate "absence over wrong data" rule already in place for lands and unshown prices.
- `CardEnrichment.layout` (Scryfall-sourced, already part of the existing enrichment pipeline) already distinguishes `transform`, `modal_dfc`, `meld`, `split`, `adventure` from `normal` and the other single-faced layouts — no new data source needed for the DFC fix.

Several independently-verified findings against real decks and Scryfall's public API shaped this fix, in the order they were found:
- **Hybrid mana renders as a genuine compound slug in `.deck-cmc`.** `Lluwen, Imperfect Naturalist` (`{B/G}{B/G}`) and `Revitalizing Repast` (`{B/G}`) both use `mtg-symbol-bg`; `Thranduil, Sindarin Liege // Silvan Rally` uses `mtg-symbol-gu` (Green/Blue) four times. Neither slug is in the current table, so all three cards currently show no mana cost at all.
- **An earlier check of a hybrid card (`Boros Charm`) suggested hybrid mana splits into two plain single-color abbrs instead of a compound slug — that turned out to be a false lead.** That check was against the card-detail modal's cost display (`.container-details .txt-mana`), a *different* component that happens to reuse the same `txt-mana`/`mtg-symbol` CSS classes but is never touched by `extractManaCost`, which only ever reads inside `.deck-cmc` (deck-list rows). Both real `.deck-cmc` observations agree on genuine compound slugs, so there's no real contradiction once the wrong component is excluded.
- **The real hybrid asset filename has no separator** (`.../symb/BG.svg`, confirmed live) — a first implementation pass used `"B/G"` as the canonical code, which `ManaCostIcons` URL-encodes to a 404ing `%2F`. Fixed to `"BG"`, matching the Phyrexian entries' existing convention (`"BP"`, not `"B/P"`) that should have been the tip-off the first time.
- **Thranduil's `layout` is `"adventure"`, not `"modal_dfc"`** — an unverified assumption in the first implementation pass. Checking `Thranduil, Sindarin Liege // Silvan Rally` against Scryfall's API directly: `layout: "adventure"`, `mana_cost: "{2}{G/U}{G/U} // {1}{G/U}{G/U}"` (both faces real). Its `.deck-cmc` row has exactly those 6 symbols concatenated, confirming the suppression problem — just under the wrong layout name.
- **The same `adventure` layout does not concatenate consistently.** `Brazen Borrower // Petty Theft` (adventure) concatenates both faces (5 symbols). `Bonecrusher Giant // Stomp` (also adventure, same deck) shows only 2 symbols — Bonecrusher Giant's own `{2}{R}`, with Stomp's `{1}{R}` never appended. No property of the card (layout, whether both faces have real costs) predicts which behavior a given adventure card gets; it looks like inconsistent manual data entry on LigaMagic's side, not a systematic rule.
- **`split` cards concatenate consistently.** `Fire // Ice` (`{1}{R}` + `{1}{U}` → 4 symbols) and `Roaring Furnace // Steaming Sauna`, a Duskmourn "Room" card also `layout: "split"` (`{1}{R}` + `{3}{U}{U}` → 5 symbols, confirmed via Scryfall's API) both concatenate exactly as expected, with no counter-example found.
- **`transform` and `meld` never concatenate.** `Delver of Secrets // Insectile Aberration` (transform) shows only `{U}` — its back face has no printed cost at all. `Bruna, the Fading Light` (meld) shows only its own `{5}{W}{W}` — a meld card's "meld back" is a separate conceptual card with no cost of its own. Neither layout has two real costs to concatenate in the first place.
- **`modal_dfc` was never directly confirmed either way**, and — given `adventure` already proved a layout value can be inconsistent across different real cards of that same layout — checking one `modal_dfc` example (even a concatenating one) wouldn't have been safe to generalize from. Not pursued further; treated the same as `adventure`.

## Goals / Non-Goals

**Goals:**
- Cards using two-color hybrid mana show their correct cost instead of none.
- Split cards never show a misleading concatenated cost — the one layout confirmed to need it.

**Non-Goals:**
- Splitting a DFC's concatenated cost into "front face only" — not attempted, since the page gives no reliable signal for where to split. (Deferred; see design.md's parent-feature note that a Scryfall-backed fallback was considered and explicitly not chosen here.)
- Suppressing mana-cost icons for adventure or modal double-faced cards. Investigated in depth (see Context) and explicitly rejected: the same layout value behaves inconsistently across different real cards on LigaMagic's side, so no layout-based rule can be correct for all of them. Fixing this properly would need per-card cost verification against Scryfall's `card_faces[].mana_cost`, which reopens a Scryfall-mana-cost dependency this change deliberately doesn't take on — left as a documented limitation instead.
- Exhaustively verifying all ten two-color hybrid pairs against live `.deck-cmc` markup — two are directly confirmed (`bg`, `gu`); the rest are included on the strength of the alphabetically-ordered two-letter convention those two consistently follow, with the same fail-soft behavior (an unrecognized real slug just drops that card's cost, same as today) protecting against a wrong guess.

## Decisions

**Add all ten two-color hybrid slugs now, not just the two confirmed ones.**
Two independent real observations (`bg`, `gu`) both follow the same alphabetically-ordered two-letter convention (the five colors sorted `b < g < r < u < w`, slug = the two letters in that order). Guessing the remaining eight costs nothing if wrong: `SLUG_TO_SYMBOL` is a plain lookup, so an entry for a slug LigaMagic never actually produces is simply dead — it can't cause a wrong decode, only a missed one (same as today, for a symbol not yet in the table). Alternative considered: add only the two confirmed pairs and extend the table "as encountered," matching the original design's stated philosophy for exotic symbols in general — rejected here specifically because the cost of being wrong is zero and the benefit (potentially fixing several more cards' cost display in one pass, without waiting for each pair to be individually reported) is real.

**Suppress mana-cost icons only for `split`, using the already-captured `CardEnrichment.layout`. `adventure` and `modal_dfc` are deliberately left unsuppressed; `transform` and `meld` are confirmed to never need it.**
This is the most-revised decision in this change. The original plan was to suppress `transform`, `modal_dfc`, and `split` uniformly. Live verification (see Context) overturned two thirds of that: `transform` never concatenates (its back face has no printed cost), and the one real card believed to be `modal_dfc` (Thranduil) turned out to actually be `adventure` — which, once checked properly, turned out to concatenate for *some* cards and not others under the exact same layout value, with no detectable distinguishing signal. Since `modal_dfc` was never directly confirmed either way, and `adventure`'s inconsistency already proves a layout value alone can't be trusted, extending that same unreliable trust to `modal_dfc` wouldn't be sound even with one confirming example. `split`, by contrast, has two independent real confirmations (`Fire // Ice`, `Roaring Furnace // Steaming Sauna`) with no counter-example, so it's the only layout suppressed.
The page still gives no way to detect concatenation from `.deck-cmc` alone (no separator, no distinct markup) — layout only becomes knowable once Scryfall enrichment resolves, and even then only tells you the layout, not whether *this specific card's* LigaMagic entry happens to concatenate. `layout` is enrichment data the app already fetches for every card regardless (for the color rail, legality check, and grouping), so reading it here adds no new network dependency, just a new use of data already in hand — consistent with why the original design rejected a Scryfall dependency for the common case.

**Gate at render time in `CardRow`, not at capture time in `mana-cost.ts`.**
`extractManaCost` has no access to `layout` (a Scryfall-enrichment concept, resolved after and independently of page capture) and shouldn't gain one — keeping capture free of enrichment concerns preserves the "page capture never depends on Scryfall" property the rest of `deck-page-capture` relies on. The suppression is purely a List-view rendering concern: `CardRow` already has `card.enrichment?.layout` available, so it checks it right where `<ManaCostIcons>` is rendered.

## Risks / Trade-offs

- **A split card's (wrong, concatenated) cost briefly shows before enrichment resolves**, since page capture completes before Scryfall responds. Mitigation: accepted — this matches the existing "eventually correct, briefly generic" behavior already true of the color rail (shows the neutral pending color until enrichment resolves) and the illegal-card badge. No card shows a *stable* wrong value; it only flashes before settling to hidden.
- **Eight of the ten hybrid slugs are unverified guesses.** If LigaMagic's real convention differs for some pair (e.g. it isn't purely alphabetical for every combination), that specific pair's cards continue to show no cost — identical to today's behavior, not a regression. Mitigation: none needed beyond noting it; safe to extend later if a real mismatch is observed.
- **Adventure and modal double-faced cards can still show a wrong, concatenated cost, with no mitigation.** This is an accepted, permanent limitation, not a transient one — unlike the enrichment-delay flash above, some adventure/modal-DFC cards will show a wrong cost indefinitely, because no reliable signal exists to detect which ones. Narrower in practice than it sounds: most Commander decks run only a handful of these layouts, and a wrong-but-present cost here is no worse than this same class of card's status before this change (cost missing entirely, for the ones that also happened to use hybrid mana) or before the original mana-cost-icons feature shipped (no mana cost shown for any card). Revisiting this would need per-card verification against Scryfall's `card_faces[].mana_cost`, deliberately out of scope (see Non-Goals).
